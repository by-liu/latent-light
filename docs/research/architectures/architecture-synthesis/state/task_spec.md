# Architecture synthesis and visual review

## Primary question

Which shared design choices explain the model deep dives, and how can each mechanism be presented clearly?

## Intended reader and use

Readers who know the basic Transformer and want to connect individual model
reports to reusable architectural ideas. Use this as a public learning module
and a navigation layer, not a benchmark leaderboard.

Learning goal: Connect model-specific studies to shared mechanisms and distinguish mathematical changes from training and runtime changes.

## Scope and time boundary

Overview, foundations connections, and Architectural Evolution; preserve the individual model studies.

Evidence boundary: Selected primary reports and existing model-study records inspected October 10, 2026. This is not an exhaustive release search.

## Exclusions

Do not rewrite the 41 individual model studies, change model release artwork, run model weights, benchmark hardware, commit, push, or deploy.

## Deliverables

- Evidence-grounded canonical report in `report.md`
- Source, claim, run, and visual ledgers
- Explicit counterevidence, uncertainty, and open questions
- Derived Latent Light pages requested by the user

## Report contract

- Canonical format: Markdown
- Desired depth: short overview pages and focused mechanism pages with optional mathematical detail.
- Citation style: Claim-local links or footnotes appropriate to the destination.
- Evidence cutoff: 2026-10-10 for the mechanisms rechecked here.
- Refresh expectation: editorial updates when a study changes a design explanation, not automatic monitoring.
- Distribution and privacy boundary: public site and repository; public sources only, no private employer material.

## Visual contract

- Plan one high-level overview after the executive answer unless it would be
  misleading or redundant.
- Run a visual checkpoint for every major section; do not impose a figure quota.
- Prefer editable, accessible, evidence-linked visuals.

## Research map

- History: execution, head sharing, latent compression, connectivity, recurrence and hybrids.
- Coordinates: RoPE, trained context extension and visual/time coordinates.
- Capacity: feature gates, selected experts, balancing and communication.
- Depth: one residual stream, constrained multiple streams, depth attention and read/write gates.
- Vision: contrastive encoders, query bottlenecks, projection, merging and depth injection.
- Skeptical pass: preserve growing global caches, selector overhead, incomparable budgets, training versus architecture boundaries, and checkpoint-specific exceptions.

## Budget and checkpoints

Three bounded passes: audit current pages/catalog; verify selected mechanisms and build purposeful visuals; independently review evidence, exports, desktop/mobile presentation and tests. Stop once each page has a clear purpose, accurate sourced mechanisms and usable visuals.

## Success criteria

Seven evolution pages including a new depth/residual page, refreshed collection overview and foundations connections. Preserve established URLs. Number figures/equations per page. Keep HTML and Markdown explanations equivalent. Full site validation and fresh browser review must pass, with existing warnings reported.

## User-supplied facts

The user requests a review informed by all model deep dives, with substantially improved visualization and presentation.
