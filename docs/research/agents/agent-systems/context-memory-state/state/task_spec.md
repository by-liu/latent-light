# Context, Memory & State: research and delivery contract

## Inquiry

Explain context, memory & state as part of the Agent Systems collection. Preserve durable concepts while rechecking mutable implementation claims.

## Intended reader and use

Readers learning to design, evaluate and control agent systems. Support both readable HTML and complete agent-consumable Markdown.

## Scope and time boundary

Selected primary sources were inspected on October 10, 2026. This is a bounded source audit, not an exhaustive survey or a performance ranking. Paper source use is restricted to abstract-supported foundational mechanisms; no paper figure or algorithm is reproduced.

## Exclusions

No private conversations, confidential work, credentials, prices, adoption recommendation or unsupported product ranking. No performance experiments were run. No automatic monitoring, commit, push or deployment.

## Deliverables

The canonical page and its references, numbered teaching visuals or equations where useful, navigation, exports and scoped regression tests. Research ledgers are not site content.

## Output contract

- Kind: site-page.
- Path: `src/content/docs/agents/context-memory-state.mdx`.
- Route: `/agents/context-memory-state/`.
- Cite consequential claims next to their use. Label independent synthesis, proposed engineering practices and elementary derivations.
- Use the page itself as the narrative output; do not maintain a duplicate report.

## Visual contract

Use a numbered native ModelFlow diagram with claim-local source citations. Its desktop flow stacks vertically on narrow screens and exports as complete text. Original diagrams use editable MDX, not image generation. Every included diagram has a visual manifest record and a page-local Figure number.

## Research map

Inspect cited paper abstracts, official specifications, documentation and first-party repositories. Separate model, harness, execution environment, procedure packaging and protocol roles. Distinguish documented capabilities from independent reliability evidence.

## Budget and checkpoints

Complete one coherent first edition. Review sources and contradictory boundaries, draft, refine diagrams and wording, run full validation, inspect browser layouts and verify exports. Future ecosystem revisions require a new source check.

## Success criteria

Correct references and evidence boundaries; no legacy workspace names or private material; coherent navigation; complete exports; passing validation and desktop/mobile checks in both themes. Existing unrelated work remains untouched.

## User-supplied facts

The user requested adaptation into Latent Light and current community information. No user anecdote is used as factual technical evidence.

## Assumptions and decisions

Keep this collection under AI Technology, alongside LLM & VLM. Separate concepts from a dated ecosystem map. Treat coding as the first system study, not the definition of every agent. Framework documentation is not a benchmark result.
