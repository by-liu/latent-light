An efficient architecture spends the device's limited memory and computation on the distinctions the task needs. A smaller weight file is only one part of that decision. The model also creates intermediate tensors, retains conversation state and moves data through a particular processor. Two models with similar parameter counts can therefore have very different deployment costs.[^mobilellm][^griffin]

This page connects architectural choices to those costs. Start with [Edge AI foundations](/edge-ai/foundations/) for the device budget and [Transformer foundations](/architectures/foundations/) for attention and feedforward blocks. The examples below are source inspection and calculations, not measurements on a phone. Sources and the released configuration were checked October 12, 2026.

## Separate three kinds of size

**Stored weights** describe learned information shared across requests. **Working activations** are temporary tensors created while processing an input. **Retained state** survives between generation steps, such as attention's keys and values. Compressing one does not automatically compress the others.[^gqa][^mamba]

For a dense decoder, a useful first approximation is a ledger of matrix sizes. Assume model width D, L independently parameterized layers, vocabulary V, gated feedforward width m, Hkv key/value heads and head width dh. Query width equals D. Input and output embeddings are tied; biases and small normalization vectors are omitted:

<MathExpression display number="1" tex="P \approx VD + L\left(2D^2 + 2D H_{\mathrm{kv}}d_h + 3Dm\right)" />

The four attention projections contribute two D by D matrices for queries and output, plus two D by Hkv·dh matrices for keys and values. A gated FFN contributes three D by m matrices. This is a Latent Light size derivation from the projection contracts, not a universal parameter formula: untied embeddings, expert banks, different head widths and shared layers change it.[^gqa][^smollm-config]

For decoding with full attention, the unreplicated KV payload is:

<MathExpression display number="2" tex="M_{\mathrm{KV}} = 2BLT H_{\mathrm{kv}}d_h s_{\mathrm{KV}}" />

B is the number of simultaneous sequences, T their retained token count and sKV bytes per key or value element. The factor two counts K and V. This excludes allocator padding, cache metadata, temporary attention buffers and any physical duplication. A backend can allocate more than the logical payload.[^gqa]

That distinction sets up the design questions: should we store fewer unique weights, keep fewer features per past token, or retain a compressed summary of the past?

## Small decoders: allocate capacity deliberately

At sub-billion scale, vocabulary matrices can consume a substantial part of the budget. Tying the output projection to the input embedding reuses one matrix; reducing the vocabulary changes both storage and tokenization. The latter must be tested on the intended languages and inputs because a lower vocabulary count is not itself a lower sequence-processing cost.[^mobilellm][^smollm-config]

MobileLLM tested deep, narrow networks against wider, shallower networks at roughly 125M and 350M parameters. The deeper variants generally did better on the tested language tasks. Its immediate layer sharing applies the same block twice in succession, seeking additional transformations without adding another set of weights. These are results within that study, not a rule that maximizing depth always improves a device model.[^mobilellm]

Reusing a block saves unique parameters but repeats computation. It may also improve weight locality when the same block remains in a fast cache. Whether that happens depends on the block's size, backend scheduling and memory hierarchy. More layers still mean more dependent operations; parameter savings do not prove latency savings.[^mobilellm]

## A worked footprint: the cache can exceed the weights

The released **SmolLM2-135M base** configuration makes a useful concrete ledger. It specifies L = 30, D = 576, m = 1,536, V = 49,152, nine query heads, three KV heads and tied embeddings. With ordinary equal-width query heads, dh = 576 / 9 = 64. Its configured context ceiling is 8,192; this is a configuration value, not evidence of equal quality at every length.[^smollm-config]

Substituting into [Equation (1)](#equation-1) gives:

<MathExpression display number="3" tex="P \approx 28{,}311{,}552 + 30(884{,}736 + 2{,}654{,}208) = 134{,}479{,}872" />

This omits normalization weights. If every counted parameter could be packed into exactly four bits, its payload would be **67.24 MB**, or **64.13 MiB**. This is an idealized calculation, not the size of an inspected quantized artifact: scales, zero points, padding and higher precision tensors add storage.

At one sequence, 4,096 retained tokens and two bytes per KV element, [Equation (2)](#equation-2) gives **94,371,840 bytes = 90 MiB**. At 8,192 tokens it gives **180 MiB**. The logical cache alone can exceed the ideal four-bit weight payload, despite the model having only about 135M parameters.

Keeping the layer count and head width fixed, replacing its three KV heads with nine would triple that cache to 270 MiB at 4,096 tokens; using one would reduce it to 30 MiB. These are hypothetical dimension changes, not interchangeable checkpoints or quality predictions.

## Attention shares heads or limits history

Multi-head attention gives each query head its own K and V head. **Multi-query attention (MQA)** shares one pair across all query heads. **Grouped-query attention (GQA)** lies between them: each group of query heads shares a pair. Queries remain distinct. This reduces KV projection width and retained cache while preserving multiple query patterns.[^mqa][^gqa]

The GQA paper converts multi-head checkpoints by pooling KV projections within groups, then performs additional pretraining. Merely changing a configuration is not the demonstrated conversion procedure. Its quality and speed comparisons use the studied T5 models and hardware; they do not establish the result for every mobile decoder.[^gqa]

Read the dashed connections in [Figure 2](#figure-2): they show which queries read a common key head. The value heads above follow the same grouping. For the depicted eight queries, logical KV payloads scale as **8:4:1**, with layer count, token count, head width and precision fixed. This is a shape ratio, not an 8:4:1 latency or quality comparison. The published figure's eight heads are illustrative; the earlier SmolLM2 example has nine queries and three KV heads.[^gqa-figure]

Limiting attention to a rolling window changes a different dimension: T becomes at most the window length for those layers, if the runtime actually evicts old state. Alternating local and global layers only bounds the local layers. [Gemma 2](/architectures/models/gemma-2/) is a worked example of that distinction; full-history layers still grow with context.[^gemma2]

| Design lever | Logical saving | What must be checked |
| --- | --- | --- |
| Tied embeddings | One fewer vocabulary matrix | Checkpoint semantics and output head |
| GQA or MQA | Fewer KV features per past token | Quality after training, physical cache layout |
| Sliding window | Fewer retained positions in local layers | Old-state eviction and long-range task failures |
| Layer sharing | Fewer unique block weights | Repeated operations, separate state, locality |
| Recurrent or hybrid blocks | A summary state, possibly a bounded attention cache | Exact retrieval and supported kernels |

This table is a synthesis of the mechanisms above and below. The savings concern different objects and should not be added as independent speed multipliers.[^mobilellm][^gqa][^gemma2][^mamba][^griffin]

## Recurrence compresses the past

A recurrent model updates a fixed-size state rather than storing an addressable vector for every past token. Mamba makes parts of its state update input dependent, so it can select information to retain or forget. Its autoregressive state does not grow with context length for a fixed architecture and batch. That does not make every implementation fast: the paper's hardware-aware scan is part of its contribution.[^mamba]

The tradeoff is information access. Attention can revisit an earlier retained token; a recurrent block must recover what its state preserved. **Griffin** combines gated recurrence with local attention, retaining a compressed long-term route and a direct recent-token route. Its copying and retrieval experiments help reveal why those routes are complementary. They do not prove that every fact in a long prompt remains recoverable.[^griffin]

This is a useful candidate for streaming tasks, but exact identifiers, quotations and rare facts deserve direct tests. A constant memory curve can coexist with a task failure curve that worsens as distractors or distances grow. Continue with [Mamba](/architectures/models/mamba/) for the selective update and [efficient inference](/edge-ai/efficient-inference/) for the execution consequences.

## Vision backbones spend spatial computation differently

For images, a compact architecture often separates spatial filtering from channel mixing. A depthwise convolution filters each channel independently; a pointwise convolution mixes channels. MobileNetV2 expands a narrow representation, applies depthwise filtering and projects back to a narrow **linear bottleneck**. Its residual path connects narrow representations, while nonlinear processing happens in the expanded space.[^mobilenet]

This illustrates a broader principle: count the intermediate tensors as well as the stored weights. The paper describes an execution strategy that avoids fully materializing large intermediates. A generic implementation that does materialize them may have a different memory profile. For multimodal systems, the vision encoder, image resolution and number of features sent to the language model belong in the same budget; see [multimodal Edge AI](/edge-ai/multimodal/).[^mobilenet]

## Sparse experts are not small stored models

Mixture of experts selects a subset of FFN experts for each token. That limits active computation, while the other experts remain learned parts of the model. Mixtral's paper explicitly distinguishes about **47B total** from **13B active** parameters and notes that serving memory follows total storage. Those rounded figures describe that large model; it is a mechanism example, not a phone recommendation.[^mixtral]

For an edge device, ask where every expert resides and how selected experts arrive. Offloading may trade resident memory for storage traffic and latency. Routing overhead, small per-expert batches and kernel support further affect execution. A dense small model can therefore be the more practical option even when a sparse model advertises a similar active count. Read [Mixtral](/architectures/models/mixtral/) for routing and [runtimes and compilers](/edge-ai/runtimes-compilers/) for backend constraints.[^mixtral]

The practical choice follows the workload: first set the task, maximum context, concurrency and input resolution; then compare actual weight, state and activation budgets. [Training capable small models](/edge-ai/training-small-models/) explains how to concentrate capability within that budget, [quantization and compression](/edge-ai/quantization-compression/) changes its numerical representation, and [evaluation and profiling](/edge-ai/evaluation-profiling/) establishes whether the complete system meets the target.
