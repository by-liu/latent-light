Use this starter with the [Model Deep Dive guide](/about/content-guidance/model-deep-dive-guide/).
It provides a flexible structure, not a section quota or a completed study.

Copy it into `src/content/docs/architectures/models/<model-slug>.mdx`.
Replace every `REPLACE_` placeholder with inspected evidence. Remove unused sections and instructional comments before adding the page to navigation.
Do not publish a scaffold with missing evidence or empty sections.

The import paths below match that source directory. `ModelResources` and `MathExpression` are globally registered.
`FocusCanvas`, `SourceFigure` and `ModelFlow` require explicit imports. The starter imports the components it uses; the independent-diagram recipe adds `ModelFlow`.

## Rendering recipes

### Dense original figures

Use the starter's `FocusCanvas` and `SourceFigure` pattern. Keep the source URL and Markdown image path identical.
Use a meaningful text equivalent, not just “architecture diagram.”

Set `minWidth` only after checking labels. Mobile should pan within the frame while desktop shows the complete figure.
Test keyboard scrolling, full-size links, dark mode, and focus view. Number later figures sequentially with matching `figure-2` anchors.

Keep the caption short. Put detailed interpretation in the following paragraph.
Record the original edition, page, figure number, crop, checksum, and reuse basis in the asset records.

### Independent mechanism diagrams

`ModelFlow` is useful for a short execution sequence or parallel paths. It is not a replacement for a more informative source architecture figure.
Use native SVG or another precise diagram when geometry, matrices, or dense branching matter.

```mdx
import ModelFlow from '../../../../components/architectures/ModelFlow.astro';

<FocusCanvas label="REPLACE_MECHANISM_PURPOSE" size="diagram">
<ModelFlow
  id="figure-2"
  title="REPLACE_MECHANISM_TITLE"
  lanesJson='[{"label":"REPLACE_PATH","steps":[{"label":"REPLACE_INPUT","detail":"REPLACE_SHAPE"},{"label":"REPLACE_OPERATION","detail":"REPLACE_COMPUTATION","accent":true},{"label":"REPLACE_OUTPUT","detail":"REPLACE_SHAPE"}],"note":"REPLACE_SCOPE_AND_STATE_BOUNDARY"}]'
>
**Figure 2.** REPLACE_SHORT_CAPTION. Independent explanation of REPLACE_SOURCE_MECHANISM.[^report]
</ModelFlow>
</FocusCanvas>
```

The Markdown export must retain every meaningful lane, step, detail, and note.
Do not expose raw `lanesJson` instead of that explanation.

### Numbered equations

Use `MathExpression` for an equation that helps explain the mechanism. Define its symbols and assumptions beside it.

```mdx
<MathExpression display number="1" tex="y = \sum_{i=1}^{k} w_i v_i" />

Here, k is the number of selected contributions, w_i is a weight, and v_i is a value vector.
State the model-specific selection and normalization rule before using this expression.
```

This is a rendering example, not a claim about any model's computation.
Use single literal backslashes in a static MDX `tex` attribute. JavaScript string escaping rules do not apply there.
Use `\lt` and `\gt` for mathematical inequalities. Let `number` supply the equation tag instead of adding a second tag.
Inspect the rendered KaTeX output. A numbering check alone cannot establish correct parsing.

## Research files and handoff

Create the study records under `docs/research/architectures/<model-slug>/`:

```text
coverage-audit.md          Mechanism and figure coverage, with source locators
state/task_spec.md         Subject, scope, constraints, and deliverables
state/progress.json        Actual progress, gaps, and completed reviews
state/sources.jsonl        Inspected editions, artifacts, and revisions
state/claims.jsonl         Consequential claims and supporting evidence
state/runs.jsonl           Commands, measurements, and validation results
state/visuals.jsonl        Selected figures, derivatives, and provenance
```

For new site studies, the MDX page is the canonical explanation, not a second
`report.md`. Record its repository-relative path in the schema 3 output contract
from the [Research workflow](/about/content-guidance/research-workflow/).
A requested standalone report can be canonical instead. Preserve existing
schema 2 reports and records without automatic migration.
Keep hashes and detailed source pins here. These files must still be safe for the public repository.
Use `public/figures/model-studies/<model-slug>/SOURCES.md` and `NOTICE.md` for public asset records and applicable notices.
Keep restricted or unclear-rights PDFs outside the public repository.

Before handoff, follow the guide's [completion checklist](/about/content-guidance/model-deep-dive-guide/#completion-checklist)
and the [site validation checks](/about/maintenance/#validate-a-change).
Review the explanation and visuals, fix the findings, then inspect the result again.
Check HTML, Markdown, MDX, navigation, search, and agent indexes.
Record only checks that actually occurred. Passing validation does not establish factual accuracy or authorize publication.
