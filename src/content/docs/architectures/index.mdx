## The questions beneath the names

Start with the question that interests you:

- **What should a model remember?** Compare [attention and memory](/architectures/evolution/attention-and-memory/), from KV sharing and latent caches to recurrent state and selected history.
- **How should it locate evidence?** Separate [position and long context](/architectures/evolution/position-and-long-context/) from a promise of reliable recall.
- **Where should it spend computation?** Understand [FFNs and experts](/architectures/evolution/ffns-and-experts/), including the difference between feature gates and routing.
- **How should information travel through layers?** Examine [depth and residual paths](/architectures/evolution/depth-and-residual-paths/).
- **How should it read an image or video?** Trace [multimodal integration](/architectures/evolution/multimodal-integration/) from pixels to usable visual evidence.

These choices can coexist. DeepSeek-V2 combines latent attention with sparse
experts; Gemma 3 combines local and global attention with a visual interface;
Kimi K3 adds selective information flow across depth.[^deepseek][^gemma][^kimi]
None is adequately described by one label such as “efficient” or “multimodal.”

## Architecture is one part of the explanation

Data, objectives, optimization, and inference budgets can change behavior without
introducing a new neural block. DeepSeek-R1 is a useful example: its reasoning
training builds on an already pretrained backbone.[^r1] Keep the computation
and the learning process separate before attributing a gain.

This is a curated learning map, not a ranking or an exhaustive release tracker.
The [model catalog](/architectures/models/) covers named releases; the
[research agenda](/architectures/evolution/emerging-directions/) explains what
evidence would improve these architectural explanations. Selected mechanisms
were rechecked October 10, 2026. No model weights or benchmarks were run here.
