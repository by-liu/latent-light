GLM-4 is worth studying as a transition from a language model to a tool-capable assistant family. The open 9B checkpoint makes its **attention and cache contract** inspectable; the family report describes how pretraining, alignment, longer context and external tools build on that network.[^report][^config]

The representative artifact here is the **original GLM-4-9B-Chat**, not the closed GLM-4 API model, the separate one-million-context release, or the later GLM-4-0414 generation. Keeping those identities separate prevents a useful family report from becoming a misleading checkpoint specification.[^report][^card]

Study scope: July 2024 report revision, original 9B-Chat configuration, tokenizer, targeted inference code and license. No checkpoint executed. Evidence checked October 10, 2026.

## Highlights

- **Much smaller persistent attention state.** Thirty-two query heads share two KV groups; attention capacity and cached history are different dimensions.[^config][^code]
- **A broader training recipe than chat fine-tuning.** The report adds large multilingual pretraining, supervised alignment, preference-based alignment and long-context adaptation.[^report]
- **Tool capability is a system capability.** The model emits a request; a runtime executes it and returns an observation. The report's All Tools system is not bundled inside a 9B weight file.[^report]
- **The release can correct an architectural assumption.** The selected code uses causal attention and one-dimensional partial RoPE, despite the report's broader discussion of two-dimensional positions.[^report][^code]

## Model in numbers

| Dimension | Value and scope |
| --- | --- |
| Parameters | Approximately 9B; artifact metadata counts 9.400B stored parameters. This is the selected 9B-Chat release, not the API model's undisclosed size.[^config][^card] |
| Decoder | 40 layers; residual width 4,096; FFN inner width 13,696; SwiGLU and RMSNorm.[^config][^code] |
| Attention | 32 query heads, two KV groups, width 128 per head; query/key/value projections include biases.[^config][^code] |
| Base data | Report explicitly states approximately 10T multilingual pretraining tokens for GLM-4-9B. The broader GLM-4 corpus is mostly Chinese/English plus 24 other languages; a complete mixture ledger is not public.[^report] |
| Context | Selected chat config: 131,072 positions. The report describes 8K base training and later context extension; the 1M variant is a different release.[^report][^config] |
| Compute | Accelerator count, complete useful GPU hours, training FLOPs and project cost undisclosed for this selected artifact in the inspected sources.[^report][^card] |

## Trace the actual network

The input is a tokenized chat sequence, including any serialized tool definitions and observations. Embeddings enter repeated causal attention and gated FFN blocks. Normalization precedes each sublayer, and a residual connection retains the incoming stream. The final projection produces next-token logits, not a browser operation or database query.[^code]

**Grouped-query attention is the main serving lesson.** For each layer, the model computes 32 query heads but only two key and two value heads. Each KV head serves 16 query heads. Cached K/V are stored before the selected implementation expands them for attention; a backend can still incur temporary expansion or other overhead.[^code]

Holding head width, layer count, sequence length and precision fixed, the persistent KV payload is 16 times smaller than a corresponding 32-KV-head design. This is not a claim of 16 times faster end-to-end inference.[^config][^code]

### Position and attention-mask boundaries

The family report describes a two-dimensional RoPE design. The inspected original 9B implementation instead takes a one-dimensional position sequence, applies rotary positions to half the head dimension, and uses a larger rotary scale for long context. This page follows that released artifact when explaining its inference contract.[^report][^config][^code]

For a full prefill without a supplied mask, the targeted code constructs a triangular causal mask or asks the attention backend to apply causal attention. During cached decoding, previously stored keys/values supply history. None of this is the original GLM's bidirectional visible-context blank-infilling mask merely because the family name is the same.[^code]

The approximately 150K tokenizer vocabulary and 151,552 padded model vocabulary are different scopes, not necessarily inconsistent counts. The released embedding/output tensors use the padded value.[^report][^config]

## The training recipe and what it discloses

The report's pretraining pipeline combines multilingual web, books, code and instruction-related content, with filtering and deduplication. It explicitly states approximately 10T pretraining tokens for GLM-4-9B and says its post-training pipeline/data follow GLM-4-0520. That connects the recipes without making the open and API models identical. A complete, independently reproducible checkpoint data manifest is not supplied.[^report]

Post-training uses authentic prompts and human interactions for supervised alignment. Preference/reinforcement learning addresses factuality, relevance and safety. The report does not fully identify every algorithm, reward model and hyperparameter for this artifact, so listing PPO or DPO as its exact pipeline would exceed the evidence.[^report]

Long context is adapted after the 8K base stage. The report references its LongAlign work and discusses position adaptation and training on long inputs. The selected 128K config establishes an input-length contract, not equal retrieval accuracy throughout that entire window. The separately released 1M checkpoint and its needle tests are not evidence that this original 9B-Chat artifact accepts one million tokens.[^report][^card][^config]

[Figure 2](#figure-2) is a **family-level All Tools architecture**, not a network diagram of the selected open 9B model. It includes external knowledge, customized assistants, Python, a browser, CogView image generation, execution and memory. The neural model proposes actions; the surrounding services carry them out and provide feedback.[^report]

This distinction matters in deployment. A function-call string does not validate arguments, authorize an action, recover from a failed service or provide persistent memory by itself. Those are application responsibilities. This is a systems interpretation of the report's separation between generation and execution, not a claim that the report evaluates every security requirement.[^report]

These selected metrics show that alignment and practical capability matter, but they do not isolate the contribution of GQA, data filtering or a particular preference algorithm. The report's long-context and agent demonstrations also depend on evaluation and runtime choices. Benchmarks should not be silently merged across base/chat/API variants.[^report]

## What remains undisclosed

The complete selected-checkpoint training token ledger, compute budget, preference-data composition and exact RL implementation remain unavailable in the inspected material. No independent benchmark reproduction is claimed here. Cache arithmetic is derived from the public dimensions, not measured process memory.

The weight license is a **custom GLM-4 agreement**, with academic-use terms and commercial-registration requirements. The official code repository uses Apache 2.0. Neither scope should be inferred from the report's CC BY figure license or from the phrase “open-source model.”[^license]

## Lessons

GLM-4 makes three boundaries concrete: **query capacity versus cached state, configured length versus usable long-context quality, and model output versus tool execution**. They are useful when evaluating any assistant deployment. Continue to [GLM-4.5](/architectures/models/glm-4-5/) for the later MoE and hybrid-reasoning recipe, or [GLM-4.1V and GLM-4.5V](/architectures/models/glm-4-v/) for its multimodal branch.
