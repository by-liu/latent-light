Qwen3-VL is an instructive example of visual evidence entering a language
decoder at more than one depth. Its design combines a visual input path,
additional feature connections, multimodal position, and staged training.[^summary]

This is a **report level study**, with a targeted source check of DeepStack
in Transformers v4.57.1. Sources were checked October 5, 2026; no released
checkpoint or processor was executed, and no full runtime trace was performed.[^report][^summary][^code]

## One input path, additional depth connections

The reported main path encodes an image or video frames and uses an MLP
merger to compress each `2 × 2` group of visual features into a token at the
language model's width. DeepStack separately takes features from three
encoder levels, projects them with dedicated mergers, and adds them at
corresponding visual positions in the first three LLM layers.[^report]

The main visual embeddings join text embeddings in the language stream.
The side features are not concatenated as three extra input sequences.
In the inspected implementation, each addition occurs after a corresponding
early decoder layer and affects only the visual positions selected by a mask.
The updated stream continues to the next layer. The additions do not create
new context positions.[^code]

For a divisible visual feature grid of height `h` and width `w`, a local count
for the main spatial merger is:

<MathExpression display number="1" tex="N_{\mathrm{merged}}=\frac{h w}{4}" />

Equation (1) counts a single feature grid, not raw image pixels, video frames,
special tokens, or a processor's final sequence. It must not be reused as a
checkpoint token count without inspecting preprocessing.

## Position and timestamps are different signals

The official summary describes Interleaved MRoPE, which spreads time, width,
and height components across rotary frequency bands. Textual timestamps
provide another way to represent video time.[^summary] The report describes
timestamps prefixed to video temporal patches.[^report]

Coordinates and timestamps expose structure; they do not by themselves
demonstrate correct temporal grounding. See
[Position and long context](/architectures/evolution/position-and-long-context/)
for the distinction between representation, accepted length, and useful reach.

## Train the interface, then the system

The report describes initial merger alignment with the vision and language
backbones frozen, followed by full parameter multimodal training and longer
context stages. It also describes supervised fine tuning, distillation, and
reinforcement learning after pretraining. These are disclosed stages, not a
fully reproducible training recipe.[^report]

The lesson is to read architecture and training together: a feature connection
specifies where information can enter, while training determines how the
system learns to use it.

## What supports the design, and what remains unknown?

The report's DeepStack ablation uses an internal `15B-A2B` language model,
200 billion pretraining tokens, and validation evaluation without post training.
That is evidence under the authors' conditions, not a measured gain for every
released model or independent replication.[^report]

A deeper study should select one checkpoint, pin processor and code versions,
trace visual token counts and injection sites, and inspect its ablations.
Do not transfer dimensions between dense and expert variants. This page
does not infer undisclosed training details or make a current leaderboard claim.
