<ModelResources reportHref="https://arxiv.org/pdf/2412.19437v1" modelHref="https://huggingface.co/deepseek-ai/DeepSeek-V3" modelName="deepseek-ai/DeepSeek-V3" />

DeepSeek-V3 scales the latent attention and sparse experts of [DeepSeek-V2](/architectures/models/deepseek-v2/), then improves the machinery that makes that scale affordable. Its distinctive contribution is a coordinated design: routing, training signals, precision, and communication are optimized together.[^report]

## Highlights

- **Balance routing without the main balancing loss.** Expert specific biases change which experts are selected without changing the weights used to combine their outputs. A small sequence balancing loss still remains.[^report]
- **Learn one more future token.** A sequential prediction module supplies an additional training objective while preserving causal conditioning. It can be discarded for ordinary inference.[^report]
- **Make low precision training selective.** FP8 matrix operations use carefully chosen scaling and accumulation, rather than converting the entire training computation blindly to eight bits.[^report]

Its research value is the connection between architectural ideas and executable systems constraints. The release provides inspectable weights and inference code, but its complete training infrastructure and data are not a turnkey reproduction.[^repo]

Study scope: original December 2024 report, relevant precision and routing appendices, original V3 configuration, official inference paths, and licenses. No checkpoint executed. Evidence checked October 10, 2026.

## Architecture and routing

The released main model has 61 layers and a 7,168 wide residual stream. The first three FFNs are dense. Other layers run one shared expert and eight selected experts from 256, each with intermediate width 2,048. MLA uses 128 query heads, a 512 dimensional KV content latent, and a 64 dimensional positional key.[^config]

[Figure 1](#figure-1) shows V3's block structure, inherited from V2, rather than a table of model dimensions. Its always active shared branch, selected routed branches, and latent attention path remain, while V3 changes their dimensions and routing control.[^report]

For routing, let <MathExpression tex="s_i" /> be a sigmoid affinity score and <MathExpression tex="b_i" /> the balancing bias for expert <MathExpression tex="i" />. Selection and weighting deliberately use different values:[^report]

<MathExpression display number="1" tex="\mathcal{E}_t=\operatorname{TopK}_i(s_{i,t}+b_i),\qquad g_{i,t}=\frac{s_{i,t}}{\sum_{j\in\mathcal{E}_t}s_{j,t}},\quad i\in\mathcal{E}_t" />

An overloaded expert receives a lower bias; an underused expert receives a higher bias. This controller updates from load statistics rather than gradients from the main balancing loss. The selected outputs retain their original affinity based weights. Equation (1) shows normalization before the release code multiplies routed weights by its 2.5 scale factor. The bias changes selection, not that scale or the underlying affinities.[^code][^config] Calling this “no auxiliary losses anywhere” would be wrong: V3 retains a small sequence level term to prevent extreme imbalance within a sequence. Routing is also limited to four nodes per token.[^report]

The tradeoff is operational complexity. Balance depends on monitoring and update rules, placement, and dispatch. Lower active parameters do not remove all to all communication or the need to store expert weights. Unlike V2's capacity policy, the reported V3 training and inference do not drop expert assignments.[^report]

Batch load feedback changes only the next step's selection bias; the shared expert bypasses this selection.[^routing][^code]

<details>
<summary>Controller schedule and what the ablation actually isolates</summary>

The bias update rate is 0.001 for the first 14.3T tokens, then zero for the final 500B. The retained sequence balancing coefficient is 0.0001. Node limited routing selects at most four nodes; the released gate computes group scores from the two largest biased scores, masks other groups, then selects the token's experts. This placement constraint does not turn the sigmoid affinities into probabilities over all experts.[^routing][^code]

Importantly, Section 4.5.3 finds that a **batch level auxiliary loss** can match bias based balancing. Its 1B model validation losses are 2.258 with sequence balancing, 2.253 with the controller, and 2.253 with batch balancing. This supports the value of a more flexible batch constraint, not a claim that every auxiliary gradient is inherently harmful. Batch balance also does not guarantee balance for a smaller domain specific inference batch.[^balance]

</details>

The report draws two possible extra depths in [Figure 3](#figure-3); the
reported V3 run uses **one**. Follow the shifted input and target tokens: each
extra depth extends its valid prefix before predicting a later token. This
is sequential prediction, not parallel heads independently predicting every
future token.[^report]

The extra module combines the preceding depth's hidden representation with the embedding of the next ground truth token, using normalization, concatenation, and a projection. A causal Transformer block then predicts the following token. Embeddings and the output head are shared with the main model.[^report]

<MathExpression display number="2" tex="\mathcal{L}=\mathcal{L}_{\mathrm{next}}+\lambda\mathcal{L}_{\mathrm{extra}}" />

Equation (2) is the one extra depth case used by V3. The additional teacher forced token belongs only to the extra target's valid prefix, not to the main next token predictor. The authors interpret denser supervision and future planning as motivations; benchmark ablations provide the evidence, rather than those interpretations proving the benefit.[^report]

At inference the main model works without MTP. A supporting backend may instead use the module as a speculative proposer and verify its proposals. Section 5.4.3 reports 85–90% second token acceptance and approximately 1.8 times tokens per second in its deployment experiment, without a complete hardware and workload protocol for that figure. These are backend results, not a guarantee that ordinary Transformers generation automatically invokes MTP.[^mtp][^repo]

## Training precision and systems

FP8 is used selectively for linear matrix operations in forward, activation gradient, and weight gradient computation. The crucial choices are **where to scale, where to accumulate, and what not to quantize**.[^precision]

| Numerical path | Reported choice and reason |
| --- | --- |
| Input activations | 1 × 128 tiles; local scales limit outlier contamination across tokens. |
| Weights | 128 × 128 blocks; all FP8 tensors use E4M3. |
| Partial sums | Promote partial accumulation to FP32 every 128 inner dimension elements to limit H800 accumulation error. |
| Sensitive network operations | Embeddings, output head, gates, normalization and attention remain higher precision. |
| Optimizer state | FP32 master parameters and gradients; BF16 first and second Adam moments. |

These choices come from Section 3.3, not the checkpoint's storage tag. Appendix B reports less than 0.25% relative loss differences versus BF16 for approximately 16B and 230B internal models. Quantizing activation gradients with a coarser block scheme instead diverged in a separate 16B, 300B token experiment. Low precision success is conditional on those protection paths.[^precision]

DualPipe feeds microbatches from both pipeline ends and overlaps attention, expert dispatch, expert computation, combination, and forward/backward work. The reported setup uses 16 way pipeline and 64 way expert parallelism with ZeRO-1, without tensor parallelism for training. Reduced bubbles trade against retaining two parameter copies. Those training choices differ from the tensor parallel inference layouts below and are not all present in the lightweight release.[^systems][^repo]

<details>
<summary>Disclosed training stages and accounting</summary>

Pretraining uses a 128K BBPE vocabulary and fills in the middle on 10% of the data. Packed pretraining examples are not separated by cross sample attention masks; packed SFT examples are. AdamW peaks at 0.00022. MTP has one extra depth, weighted 0.3 for the first 10T tokens and 0.1 for the final 4.8T. YaRN extension uses two 1,000 step stages at 32K and 128K.[^training]

SFT trains for two epochs. Reasoning examples include outputs shaped using an internal R1 model and expert generators; nonreasoning examples include V2.5 generations checked by humans. GRPO then uses rule based verification where possible and model based rewards for less directly verifiable responses.[^report]

The often cited financial number is an estimate using a stipulated two dollars per H800 hour. It covers the reported official training run, not the cost of inventing the method, collecting data, failed experiments, hardware acquisition, or all staffing. Accelerator hours, FLOPs, and total project cost are different quantities.[^report]

</details>

## Inference and evaluation

The official inference implementation has separate absorbed latent attention and ordinary expanded attention paths. In the absorbed path, cached content latents and positional keys are used directly; selected expert outputs and shared outputs are combined before returning to the residual stream. Quantized checkpoint storage and actual runtime precision are separate choices. The absorbed path projects queries into the 512 dimensional cached latent, mixes that latent history, and applies the value projection afterward; it does not reconstruct full old KV states before cache lookup.[^code][^config]

The report separates prompt processing from generation in its production deployment:[^systems]

| Serving stage | Example reported deployment |
| --- | --- |
| Prefill | 32 H800 GPUs, TP4, DP8 and EP32; two attention/MLP microbatches overlap work. |
| Decode | 320 H800 GPUs, TP4, DP80 and EP320; placement replicates hot experts to reduce imbalance. |

These are system configurations for the authors’ workloads, **not minimum hardware requirements to load the weights**. Batch composition, expert replication, shared expert placement and attention cache traffic affect achieved throughput.[^systems]

Targeted ablations are more informative than the headline final scores. Table 4 tests MTP on internal 15.7B and 228.7B models while retaining the same data and other architecture, and discards MTP for inference. Table 5 tests bias based routing on 15.7B and 228.7B models. Large model HumanEval improves from 40.2 to 46.3 under that comparison, but MMLU falls from 68.3 to 67.2. “Better on most tested tasks” is not “uniformly better.”[^report]

Post trained scores also include data curation, distillation, and alignment. They do not isolate routing, FP8, or MLA. The final comparisons have benchmark specific prompts and budgets in Section 5.3, rather than one universal sampling setup.[^report]

## Limits and lessons

V3 still needs substantial hardware to hold hundreds of billions of stored parameters. Compressed cache grows with sequence length; efficient serving additionally depends on expert placement, batching and communication. The report's original license is the DeepSeek Model License for weights, with use restrictions, and MIT for code. Later model releases must be assessed separately.[^license][^repo]

Study V3 as a system of interacting choices. Better routing supplies capacity without the same gradient constraint; MTP changes learning signals; selective precision and pipeline scheduling make the computation practical. Continue to [DeepSeek-R1](/architectures/models/deepseek-r1/) to see what changes when reasoning behavior becomes the main post training target.
