Architectural evolution is not a ladder of increasingly superior models.
It is a set of choices about what information to preserve, where to move it,
and how much computation to spend. A useful comparison names the operation
that changes and the budget it affects.

[Figure 1](#figure-1) provides four views of information flow. Position changes
the geometry of matching; training teaches the routes what to carry.
An encoder such as BERT, an encoder and decoder such as T5, and a causal language
decoder have different visibility and output contracts. Do not silently
assign the decoder schematic to every model.[^bert][^t5]

The original [GLM](/architectures/models/glm/) adds another instructive contract:
observed context is bidirectional, while missing spans are generated
autoregressively. Its mask, target order and positional representation must
be read together. A family name is not proof that later checkpoints retain
that exact computation.[^glm-original]

## Separate four kinds of change

| Layer of explanation | Example | Do not confuse it with |
| --- | --- | --- |
| Mathematical computation | GQA shares KV heads; MLA compresses KV content.[^gqa][^deepseek] | A faster kernel for an unchanged operator |
| Learned behavior | Reasoning RL changes a policy on a pretrained backbone.[^r1] | A new attention block |
| Execution | FlashAttention tiles exact attention and reduces memory traffic.[^flash] | Removal of dense pairwise arithmetic |
| Application system | Tools, retrieval and context management around a model | Capabilities supplied by weights alone |

The last row is a system boundary used here, not a specific product claim.
Model reports can change several rows at once. That makes a stronger final
model possible, but makes attribution to one ingredient harder.

## Read any change in five steps

1. Name the problem and baseline.
2. Locate the operation, route, or stored representation that changes.
3. Identify what stays the same.
4. Compare quality, active computation, retained state, total weights, and communication.
5. Inspect the experiment and implementation before generalizing.
