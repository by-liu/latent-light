Position tells a model where evidence belongs. A context limit tells you how
much input a system accepts. Neither tells you how reliably the model uses
that input. Keep **representation, capacity, visibility, and usefulness**
separate when reading a long context claim.

## Position changes matching geometry

The original Transformer adds sinusoidal position vectors to embeddings.
RoPE instead rotates query and key feature pairs before their dot product.
It exposes relative displacement through matching geometry rather than
adding another vector to the residual stream.[^transformer][^rope]

For one feature pair, with column vectors q and k:

<MathExpression display number="1" tex="R(a)=\begin{bmatrix}\cos a&-\sin a\\\sin a&\cos a\end{bmatrix}" />

At positions m and n, the rotated dot product becomes:

<MathExpression display number="2" tex="\bigl(R(m\theta)q\bigr)^\top R(n\theta)k=q^\top R\bigl((n-m)\theta\bigr)k" />

θ is the frequency for this pair. [Equation (2)](#equation-2) follows from
the orthogonality of rotation. Real heads contain many pairs with different
frequencies; content still determines the score.[^rope]

[Figure 1](#figure-1) does not mean a complete model is invariant to every input shift.
Masks, boundaries, content, and other position handling remain part of its
computation. Nor does a rotation formula establish reliable extrapolation.

## Four questions behind a long context claim

| Question | What to inspect | What it does not establish |
| --- | --- | --- |
| Representation | Position IDs, frequencies, scaling, image and time coordinates | Reliable performance at an unseen length |
| Capacity | Trained length, configured limit, backend, memory and processor | Every accepted position is used well |
| Visibility | Dense, local, compressed or selected history | A long input means every layer directly reads all of it |
| Usefulness | Retrieval, reasoning, ordering and failures across positions | A single needle test proves every long document task |

This is an interpretation framework used here, not a performance table.
Compare it with [Attention and memory](/architectures/evolution/attention-and-memory/),
which explains how visibility and storage change.

### Extend the learned positional regime

YaRN adjusts RoPE frequencies by their wavelength regimes and applies
attention scaling. It pairs that adaptation with additional training, rather
than establish a universal rule that changing one configuration value is enough.[^yarn]
[DeepSeek-V2](/architectures/models/deepseek-v2/) and
[Qwen2.5 1M](/architectures/models/qwen2-5-1m/) show why trained length,
extension technique, accepted length, and evaluation length must be recorded separately.

Qwen2.5-1M also uses Dual Chunk Attention: it remaps within-chunk, neighboring
and distant positional relationships to ranges seen during training. This is
not KV compression or simply dropping distant tokens. Remapping can make
distinct long distances look similar; useful recall still needs evaluation.[^qwen1m]

### Let depth carry information beyond a local window

In Mistral's sliding attention, a layer reads nearby positions, while
representations can carry information farther through stacked layers.[^mistral]
A theoretical path does not guarantee that the necessary detail survives it.
Local visibility and successful distant recall are different claims.

## Images and video need coordinates, not just indices

“Two dimensional” does not always mean image height and width. Original
[GLM](/architectures/models/glm/#blank-infilling-step-by-step) uses learned
coordinates for a missing span's location and progress inside that span.
It is a task-specific positional design, not multimodal RoPE.[^glm]

An image has height and width. A video adds time, and sampling rate changes
which frames become visible. Qwen2.5-VL aligns temporal rotary positions
with elapsed time; Qwen3-VL adds explicit timestamp text and interleaves
rotary frequencies across temporal and spatial coordinates.[^qwen25][^qwen3]

## Test useful reach, not only accepted length

Vary evidence location, distractor count, and dependency distance independently.
Include several facts that must be combined, conflicting evidence, and questions
whose answer changes when the relevant evidence changes. For video, vary FPS
and event timing separately. Report accuracy alongside state and latency.

These are proposed checks, not results measured here. Selected mechanisms
rechecked October 10, 2026. [Gemma 3](/architectures/models/gemma-3/) supplies
useful local/global and position ablations; the
