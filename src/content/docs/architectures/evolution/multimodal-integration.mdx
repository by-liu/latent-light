Attaching an image does not tell us how a model uses it. Follow the evidence:
**what the encoder preserves, how many representations reach the language side,
and where they enter the computation**. A vision encoder, connector, and training
recipe jointly define that interface.[^clip][^blip][^llava][^qwen]

## Four interfaces, four different jobs

<FocusCanvas size="diagram" label="Contrastive matching, learned visual queries, projection and depth injection">
<ArchitectureAtlas kind="vision" id="figure-1">

**Figure 1.** Matching images and text is different from conditioning a language decoder. Independent comparison of the named interfaces; feature counts are illustrative.[^clip][^blip][^llava][^qwen]

</ArchitectureAtlas>
</FocusCanvas>

**CLIP** learns comparable image and text representations with contrastive
supervision. It can provide a visual backbone or retrieval representation;
CLIP alone does not generate a language response.[^clip]

**BLIP-2** learns queries that read frozen vision features. In its generative
stage, projected query outputs condition a frozen language model.[^blip]

**LLaVA** maps vision features directly into language embedding space.
The original uses a linear projection; LLaVA-1.5 uses an MLP connector.[^llava][^llava15]

**Qwen3-VL** adds another route: merged input tokens plus intermediate vision
features injected at early decoder depths through DeepStack.[^qwen]
That changes where evidence enters, not merely how many input tokens are added.

The interfaces in [Figure 1](#figure-1) are useful comparisons, not a sequence in which each interface makes
the previous one obsolete. Training data, task, resolution and budget remain
part of the result.

The snowflakes in [Figure 2](#figure-2) mark frozen weights. The upper branch
conditions a causal decoder; the lower branch shows an encoder and decoder
variant. The same connector idea can therefore cross different language
model contracts. The paper uses 32 learned queries: the language input need
not include every encoder feature.[^blip]

A bottleneck controls computation but can omit detail the question requires.
That is a design concern to test, not a claim that fewer tokens always cause
lower accuracy.

## Count patches, merged tokens, and views separately

For image height H, width W and square patch side P:

<MathExpression display number="1" tex="N_{\mathrm{patch}}=\frac{H}{P}\frac{W}{P},\qquad N_{\mathrm{merged}}=\frac{N_{\mathrm{patch}}}{r^2}" />

The first count assumes divisible dimensions with no padding or crops. The
second assumes every r × r patch neighborhood becomes one output token.
It is a local geometry calculation, not a complete processor specification.
Actual models may add class tokens, delimiters, crops, frame grouping or
different resamplers.[^vit][^qwen2]

[Figure 3](#figure-3) isolates the geometry. Qwen2-VL merges neighboring visual features; Gemma 3 uses a compact fixed
token budget per encoded view, with extra crops when needed. More views can
therefore increase the aggregate budget even when the count per view is fixed.[^qwen2][^gemma]
For video, sampling changes the number and coverage of frames before
position encoding begins. See [Position and long context](/architectures/evolution/position-and-long-context/#images-and-video-need-coordinates-not-just-indices).

## Architecture and training must agree

| Question | Why it changes the interpretation |
| --- | --- |
| What is frozen, and at which stage? | A small trained interface and joint backbone training have different adaptation budgets |
| What is supervised? | Matching, captioning, instruction following and grounded coordinates teach different behavior |
| What is compressed or omitted? | Fine print, small objects or brief events may disappear before language computation |
| Where do features enter? | Input projection, cross attention and depth additions create different routes |

This is a comparison framework. The [InternVL 3](/architectures/models/internvl-3/),
[GLM vision](/architectures/models/glm-4-v/), and
[Gemma 3](/architectures/models/gemma-3/) studies provide additional training
and processor contrasts. Do not transfer one checkpoint's frozen stages,
token count or resolution rules to an entire family.

## Check whether the answer depends on the evidence

Compare correct, absent, swapped and contradictory images. Include small
text, chart values, spatial relations, and questions requiring several regions.
Control resolution, view count, data and training budget when testing an interface.

These are proposed tests, not measurements here. Selected mechanisms
rechecked October 10, 2026. Continue with [Qwen3-VL](/architectures/models/qwen3-vl/)
for original framework artwork and a concrete DeepStack implementation trace.
