## Compare the system boundaries

Read across the table to compare responsibilities, then open a study for its
source details and qualifications. Interface names alone cannot establish
execution location or isolation.

| --- | --- | --- | --- | --- | --- |

| Control question | Inspect permission and execution settings | Separate approval from filesystem/network containment | Supply external containment; no built-in resource permission system | Inspect allow/ask/deny rules and host access | Inspect the mounted guards and preview limitations |

</FocusCanvas>

This table is our comparison lens, informed by the detailed contracts cited in
the individual studies. It does not score reliability or security. “Supports
memory” is particularly weak as a comparison: active context, a recoverable
session record and remembered knowledge solve different problems. LangGraph's
checkpointer/store distinction offers another concrete example of these scopes.[^langgraph]

A meaningful trial would hold the task, model where possible, environment and
total budget fixed, then inspect outcomes, recovery and cost. If models or
scaffolds differ, report that difference instead of attributing the entire
result to the product name. See [Evaluation](/agents/evaluation-reliability/).

## Frontier

Several active directions are changing what a useful harness needs to provide.
The evidence below mixes inspected research with labeled vendor engineering
accounts. Each supplies a bounded lesson.

### Durable sessions beyond one running process

Anthropic's managed architecture separates the session log, harness and sandbox.
The record can survive a failed harness, while the next harness reconstructs
work from events. Its account explicitly distinguishes the full session from
Claude's selected context window.[^managed] OpenAI's Agents API similarly assigns
managed harness and session responsibilities to the service, with environment
choices remaining explicit.[^api]

The practical question is what can be recovered after an interruption.
Persisted text is useful, but an external operation may have committed before
its response was lost. Durable execution must reconcile effects as well as
reconstruct a conversation. These vendor designs do not prove that every
application using them already implements that recovery contract.

### Evolving context with accountable updates

ACE studies context adaptation without changing model weights. It separates
generation, reflection and curation, then merges incremental context updates.
[Figure 2](#figure-2) shows the authors' mechanism. The reported evaluations concern
particular tasks and baselines; they do not establish universal improvement
from accumulating more memory.[^ace]

The important design question is **who may revise stored guidance, with what
evidence and rollback**. An incremental memory entry can preserve a useful
lesson or preserve an error. The paper's mechanism motivates explicit review
of context changes rather than treating a longer prompt as a guarantee.

### Coordination that fits the task

Kim and colleagues compare agent architectures across multiple benchmark,
model and configuration settings. Their reported results vary with task
structure: decomposable work and sequential planning do not benefit equally
from coordination. The paper identifies overhead and error propagation as
consequential factors.[^scaling]

That supports a conditional design rule: add workers to resolve a particular
failure or independent work split, then measure the whole job. It does not
establish that all multi-agent systems help or fail. The
[coordination chapter](/agents/orchestration/) explains the contracts and costs.

### Feedback that can actually distinguish improvement

Anthropic's application-development account uses an evaluator that interacts
with the running application and is calibrated against explicit criteria.
It also reports much greater cost in one multi-agent comparison and describes
simplifying the harness as the generator model improved.[^harness]

This is a vendor engineering account with selected examples, not a controlled
ranking of these five products. Its useful lesson is that a critic needs
observable evidence and a discriminating rubric. A more capable model can also
change which scaffolding earns its overhead. Repeated self-approval is not
verification.
